# Batch-invariant mode (`flashinfer.batch_invariant`)

Deterministic, batch-invariant kernels behind one keyword: `batch_invariant=True`. The kernels are CuTe-DSL kernels
generated by an engine whose reduction orders are proved in Lean and checked bit for bit on the device; they are the
FlashInfer port of the [RL-ready kernels](https://github.com/flashinfer-ai/flashinfer) sandbox. This directory holds
the engine pieces the wired classes need, one subpackage per op family (`quant/` today), and the Lean project
(`lean/`, sources in the repository, excluded from the wheel).

**Why.** RL post-training scores every sampled token twice, once in the sampler and once in the trainer, and the
objective assumes both see the same numbers. Ordinary GPU kernels give a token different bits depending on who else
is in the batch, which tile the dispatcher picked, or whether it ran as prefill or decode. The batch-invariant mode
makes a token's bits a function of its inputs and a named class fingerprint only, whatever the batch, configuration
or path.

## The guarantee

For every wired API, every supported input, within one named environment (architecture, driver, toolchain,
FlashInfer version):

| | Property | Meaning |
|---|---|---|
| R1 | Run-to-run determinism | same inputs, same configuration, same path: same bits, across processes, streams, CUDA-graph replay |
| R2 | Batch invariance | a row's bits depend only on its own inputs and the fixed dimensions, not on batch size, padding, position, neighbours or SM count |
| R3 | Configuration agreement | every configuration in the enumerated space gives the same bits, so the dispatcher's choice (by M, SM count, anything) never touches numerics |
| R4 | Cross-path agreement | the members of one class (here: the three scale-factor layouts, fp32 inputs and their exact 16-bit widenings) give the same bits |

Each class has one **canonical dataflow**, fixed once, named as a **consistency class** and hashed into a
**fingerprint**. Anything that changes the dataflow is a different class by design. Bitwise equality is the acceptance
criterion of every test; tolerances are never used to pass one.

## The flag

* Every wired FlashInfer API gains a keyword-only argument after a `*` separator: `batch_invariant: bool = False`.
  With the default nothing changes for anyone.
* `batch_invariant=True` runs the batch-invariant class and **never falls back**: an unsupported shape, dtype,
  layout, device or architecture raises `flashinfer.batch_invariant.BatchInvariantUnsupportedError` (a `ValueError`)
  whose message names the class and the limit. It never routes to a non-invariant kernel.
* `backend`: the batch-invariant kernel is reachable **only through `backend="auto"`**. `batch_invariant=True` with any
  other `backend` value raises `ValueError`. Where `"auto"` was not an accepted value before, it is added, and with
  `batch_invariant=False` it routes to what the API's default did before (`mxfp8_quantize`: `"auto"` behaves as
  `"cuda"`); the parameter's default value itself does not change.
* Architectures: SM100 (B200), SM103 (B300), SM107 (Rubin): the tcgen05 parts. Elsewhere `batch_invariant=True` raises.
* The receipt: `flashinfer.batch_invariant.fingerprint(op, **dims)` returns the fingerprint of the class the API `op`
  computes for the fixed dimensions `dims`. The guarantee is scoped to `(fingerprint, FlashInfer version,
  architecture)`: record the three with the output. A fingerprint change is a release-note item.

```python
import torch
import flashinfer
from flashinfer.batch_invariant import fingerprint

x = torch.randn(1000, 4096, dtype=torch.bfloat16, device="cuda")
q, sf = flashinfer.mxfp8_quantize(x, backend="auto", batch_invariant=True)          # the class mxfp8.quant
q1, sf1 = flashinfer.mxfp8_quantize(x[7:8], backend="auto", batch_invariant=True)   # the same row alone ...
assert torch.equal(q[7:8].view(torch.uint8), q1.view(torch.uint8))                  # ... is the same bits (R2)
print(fingerprint("mxfp8_quantize"))                                                # 'mxquant-mxfp8-9018bd1627b3e72a'
```

## The classes

| Class | API | Fingerprint | Dataflow |
|---|---|---|---|
| `mxfp8.quant` | `mxfp8_quantize(input, is_sf_swizzled_layout, alignment, enable_pdl, backend="auto", sf_swizzle_layout, batch_invariant=True)`: bf16 / f16 / fp32 inputs of shape `(..., K)` with `K % 32 == 0`, the three `SfLayout`s (128x4 / 8x4 swizzled, linear), `alignment` padding, PDL | `mxquant-mxfp8-9018bd1627b3e72a` (independent of K, the input dtype and the layout) | TransformerEngine's MXFP8 chain, per 32-element block: `amax = fmax-tree(fabs(x_i))` (a fixed pairwise tree over the exactly widened inputs), `sf = cvt.rp.satfinite.ue8m0(mul.rn(amax, fp32(1/448)))`, `inv = div.rn(1, sf)` (exactly `2^(127 - e8)` at every byte, byte 0 included), `q_i = cvt.rn.satfinite.e4m3(mul.rn(x_i, inv))`; `-0` keeps its sign |

Where FlashInfer's own `cute-dsl` / `cuda` MXFP8 kernels differ from the class the test pins the difference, it does
not relax anything: FlashInfer zeroes the codes of a block whose amax is below `448 * 2^-127` (its inverse scale is 0 at
UE8M0 byte 0; the class keeps the values with the exact `2^127` inverse), and a `-inf` element saturates to `-448` in
the class where FlashInfer's `inf * 0` clamp gives `+448`. On every other input the three backends are bit-identical
(`tests/batch_invariant/test_mxfp8_quantize.py::test_fi_cute_dsl_is_bitwise_identical`).

The dispatcher (`quant/mx_schedule.py::default_config`) is a closed-form rule of `(M, K, element bytes, SM count,
layout)` with no measured table; every configuration it can return is a member of the enumerated space
(`all_valid_configs`), so the pick never changes bits. The compiled kernel is keyed by `(dtype, Kbp bucket,
configuration, format, recipe, layout, PDL)` and **never by M**: one specialization serves every row count.

## How it works

```
quant/mx_spec.py     the dataflow written once against an abstract FP algebra (TermAlgebra / exact CPU / torch / CuTe)
                        ├── symbolic term  → lean/RLKernels/Cases.lean (generated; Lean proves every placement folds to it)
                        ├── exact CPU bits (fp32.py: Fractions, RNE, subnormals; mx_reference.py) → what the GPU must reproduce
                        └── device code through cute_fp.py (round-to-nearest intrinsics only; no contraction, no fast math)
quant/mx_schedule.py the enumerated configuration space (what R3 is claimed over) and the closed-form dispatcher
canon.py             the engine: reduction + placement → plan of reduction steps; the kernel executes the plan
quant/blocks.py      the kernel's building blocks (declared conversions, the block amax, the scale-factor stores)
quant/mx_kernel.py   the CuTe-DSL kernel: plumbing around the plan (loads, predicates, packs, stores); K and M runtime
jit.py               compiled kernels in FlashInfer's CuTe-DSL cache, keyed by the source closure of the module
```

Every floating-point operation in a kernel goes through `cute_fp.py` (NVVM intrinsics with an explicit `.rn`
rounding) or is a declared conversion primitive (`cvt.rp.satfinite.ue8m0x2.f32`, `cvt.rn.satfinite.e4m3x2.f32`); the IR
pin test checks the compiled kernel contains nothing else (no `arith` float ops, no `math` dialect, no fast math, no
`rcp.approx`, no `ftz`, no 16-bit intermediates).

## What is proved, tested, assumed

| Claim | Status | Where |
|---|---|---|
| Every placement of the block amax computes the canonical tree; scale and codes are `Equiv`, hence bit-equal under any commutative interpretation (R3 in the model) | proved | `lean/RLKernels/Canon.lean` (`config_invarianceC`), `MXQuant.lean` (`block_amax_invariance`, `block_outputs_invariant`, `sf_bits_equal`) |
| The zero-filling bucket kernel (blocks beyond K, rows beyond M read as +0) equals the absent-dropping spec bit for bit | proved under the restricted identity `fmax(v, +0) = v` for `v >= +0` | `Semantics.lean` (`execC_pad_good`), `MXQuant.lean` (`blockamax_padded_bits`) |
| A block's outputs depend on its 32 inputs alone; determinism, batch / permutation / sub-batch invariance on the launch model (R1, R2) | proved (by construction of the model) | `MXQuant.lean` (`block_locality`, `batch_invariance`, ...) |
| The two swizzled layouts are bijections of the padded grid onto the buffer (R4 within the class) | decided (`native_decide`: one of the eight `Lean.ofReduceBool` table checks) | `MXQuant.lean` (`layout128x4_bijective`) |
| The emitted terms are the terms Lean checks, node for node | tested (regenerate + byte-compare, no toolchain; `lake build` of the generated cases by kernel `decide` in the Lean tier) | `lean_cases.py`, `tests/batch_invariant/test_mxfp8_quantize.py` |
| The compiled kernel contains only `.rn` arithmetic and the declared conversions | tested per code path, device-free | `tests/batch_invariant/test_ir_pins.py` |
| The device computes the exact CPU model (R1-R4 on silicon) | tested bitwise over the space, adversarial inputs, FlashInfer's kernels as a second oracle | `tests/batch_invariant/test_mxfp8_quantize.py` |
| `cvt.rp.satfinite.ue8m0x2.f32` and `cvt.rn.satfinite.e4m3x2.f32` compute the CPU model | assumed per architecture; the UE8M0 conversion tested over every binary32 bit pattern (nightly) | `quant/mx_sweep.py` |

No `sorry` anywhere. The axiom claim is: **Lean's standard axioms (`propext`, `Classical.choice`, `Quot.sound`), plus
`Lean.ofReduceBool` for eight named exhaustive table checks.** `Lean.ofReduceBool` is the axiom behind `native_decide`:
it trusts the compiled evaluator (Lean's code generator and interpreter) for the evaluation of a closed Boolean term,
instead of the kernel's own reduction. Every engine and class theorem, and every generated conformance case (kernel
`decide`), is free of it; the eight exceptions are the two decided layout bijections (`layout128x4_bijective`,
`layoutLinear_bijective`: 6144 and 8320 offsets), the three UE8M0 fact tables (`ue8m0_powers_fixed`,
`ue8m0_roundings`, `ue8m0_saturates`) and the three generated UE8M0 conversion tables (`ue8m0_model_matches_{rp,rz,rn}`:
531 magnitudes under three roundings), where `ue8m0Byte` is defined through `Nat.log2`, a well-founded recursion the
kernel does not evaluate. `lake exe axioms` enforces exactly this policy and names the eight theorems.

## Running the tiers

```bash
# quick tier (every CI job): device-free everywhere; GPU tests skip cleanly off SM100 / SM103 / SM107
pytest tests/batch_invariant -q

# IR pins (device-free, needs the CuTe DSL and its ptxas): one compile per code path
pytest tests/batch_invariant/test_ir_pins.py -q

# nightly tier: the full enumerated spaces and the exhaustive UE8M0 device sweep (2^32 bit patterns)
FLASHINFER_BI_NIGHTLY=1 pytest tests/batch_invariant -q -m nightly

# Lean tier: lake build + the conformance executable + the axioms check (needs elan; see "How to check the proofs")
FLASHINFER_BI_LEAN=1 pytest tests/batch_invariant/test_lean.py -q -m lean

# regenerate the Lean cases after a change to the Python spec / engine
python -m flashinfer.batch_invariant.lean_cases

# precompile the dispatcher's kernels device-free (spawned workers, 16 by default, load-gated)
CUTE_DSL_ARCH=sm_100a python -m flashinfer.batch_invariant.quant.mx_precompile --space dispatch

# heatmaps through the FlashInfer API (CUPTI kernel time, cold L2): ours vs FlashInfer's cute-dsl backend
python benchmarks/bench_mxfp8_quantize_batch_invariant.py --layout swizzled_128x4 --dtype bf16
```

Compiled kernels live in FlashInfer's CuTe-DSL cache (`FLASHINFER_WORKSPACE_BASE/.cache/flashinfer/<version>/<arch>/cached_ops/batch_invariant_mx_quant_<arch>_cute_dsl/`);
`FLASHINFER_CUTE_DSL_DISABLE_CACHE=1` bypasses it. The cache key is the hash of the module's source closure (the files
listed in `jit.py`): an edit to the engine or the kernel invalidates the module, an edit to the API, the references or
the tests does not.

## How to check the proofs

The Lean checks run by hand for now (a CI job follows once the project has a runner for it); the device-free
byte-compare of the generated cases runs under the normal pytest on every CI job.

```bash
# the pinned toolchain (lean/lean-toolchain: leanprover/lean4:v4.15.0) through elan; no Mathlib, no other dependency
curl -sSfL https://raw.githubusercontent.com/leanprover/elan/master/elan-init.sh | sh -s -- -y --default-toolchain none
export PATH="$HOME/.elan/bin:$PATH"
cd flashinfer/batch_invariant/lean

lake build                     # elaborates the engine theorems, the class and the generated cases (~1.5 min cold: the cases are closed by kernel decide)
#   ... info: 'RLK.MXQuant.block_amax_invariance' depends on axioms: [propext, Quot.sound]    (Check.lean prints the audit)
#   Build completed successfully.

lake build conformance axioms  # the two executables
lake exe conformance | wc -l   # the Lean model's terms for the generated cases: 67 lines, compared with the Python side by the Lean test tier
lake exe axioms                # the axiom policy over every declaration of the library
#   axioms check: 637 user declarations of RLKernels.*, 8 named table theorems decided by native_decide (Lean.ofReduceBool), 0 with sorry, 0 violations
```

`lake exe axioms` exits non-zero and names the declaration on any `sorry` or any axiom outside the policy. The pytest
form of the same three steps is `FLASHINFER_BI_LEAN=1 pytest tests/batch_invariant/test_lean.py -q -m lean`.

## Layout

```
__init__.py        fingerprint(op, **dims), class_name(op), CLASSES, BatchInvariantUnsupportedError, SUPPORTED_ARCHS
support.py         the architecture gate (check_device) and the backend rule (resolve_backend)
canon.py           the canonical hierarchical-reduction engine (Reduction, Placement, Plan, init_state / run_steps, trace)
term.py            hash-consed symbolic terms, the canonical S-expression, fingerprints
fp32.py            exact IEEE binary32 / bf16 / f16 arithmetic (Fractions), the e4m3 / e2m1 / UE8M0 conversions
cute_fp.py         the only floating-point primitives a kernel may use (.rn intrinsics, exact primitives)
cvt_fp8.py         the declared cvt.rn.satfinite.{e4m3,e5m2}x2.f32 primitive
dtypes.py          name <-> CuTe dtype
jit.py             FlashInfer-JIT glue (source-closure cache key; wipe only on definite evidence; compile outside the lock)
kernel_names.py    the kernel-name mirror for the precompiler
lean_cases.py      emits lean/RLKernels/Cases.lean from the Python spec
testing.py         adversarial inputs for the bitwise tiers
quant/             mx_spec, layout, blocks, mx_kernel, mx_schedule, mx_reference, reference, mx_api, mx_precompile, mx_sweep
lean/              lakefile, lean-toolchain, RLKernels/{Canon,Semantics,Support,MXQuant,Export,Cases,Check}.lean, Main.lean, Axioms.lean
```

This README is the contract within FlashInfer. The Lean library keeps the engine's namespace (`RLK`, "RL-ready
kernels") so later ports of further classes stay copies of their source.
